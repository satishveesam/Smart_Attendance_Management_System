## 🚀 Getting Started

### Prerequisites

Ensure you have the following installed:

- **Java 21** — [Download](https://adoptium.net/)
- **Maven 3.8+** — [Download](https://maven.apache.org/)
- **Node.js 18+** — [Download](https://nodejs.org/)
- **MySQL 8.0+** — [Download](https://dev.mysql.com/downloads/)
- A modern browser (Chrome recommended for face recognition)

---

### 1. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/smart-attendance-management-system.git
cd smart-attendance-management-system
```

---

### 2. Backend Setup

#### 2.1 Configure the Database

Create a MySQL database (or let Spring Boot auto-create it):

```sql
CREATE DATABASE attendance_db;
```

#### 2.2 Update Application Properties

Edit `backend/src/main/resources/application.properties`:

```properties
# Database
spring.datasource.url=jdbc:mysql://localhost:3306/attendance_db?createDatabaseIfNotExist=true&useSSL=false&serverTimezone=UTC
spring.datasource.username=YOUR_MYSQL_USERNAME
spring.datasource.password=YOUR_MYSQL_PASSWORD

# JWT Secret (change this in production!)
attendance.jwt.secret=your-256-bit-secret-key-here
attendance.jwt.expiration-ms=86400000

# Default Office Geofence (Latitude, Longitude, Radius in meters)
attendance.geofence.latitude=12.971598
attendance.geofence.longitude=77.594562
attendance.geofence.radius-meters=100.0
```

#### 2.3 Build and Run the Backend

```bash
cd backend
mvn clean install
mvn spring-boot:run
```

The backend API will start at: **`http://localhost:8080`**

Swagger UI available at: **`http://localhost:8080/swagger-ui.html`**

---

### 3. Frontend Setup

```bash
cd frontend
npm install
npm run dev
```

The frontend dev server will start at: **`http://localhost:5173`**

---

### 4. Default Login Credentials

When the backend starts, the system auto-creates the default admin account:

| Role | Email | Password |
|---|---|---|
| **Admin** | `admin@company.com` | `Admin@123` |
| **Employee** (added by admin) | `<employee-email>` | `Welcome@123` |

> ⚠️ Change default passwords immediately in production.

## 📡 API Reference

All API endpoints are prefixed with `/api`. The full interactive API documentation is available at `/swagger-ui.html`.

### Authentication
| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/auth/login` | Login and receive JWT token |

### Employees (Admin)
| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/employees` | List all employees |
| `POST` | `/api/employees` | Create a new employee |
| `PUT` | `/api/employees/{id}` | Update employee details |
| `DELETE` | `/api/employees/{id}` | Remove an employee |

### Attendance
| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/attendance/checkin` | Employee check-in (with selfie + GPS) |
| `POST` | `/api/attendance/checkout` | Employee check-out (with selfie + GPS) |
| `GET` | `/api/attendance/today` | Today's attendance status |
| `GET` | `/api/attendance/history` | Personal attendance history |

### Reports (Admin)
| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/reports` | Filtered attendance logs |
| `GET` | `/api/reports/export/pdf` | Export filtered logs as PDF |
| `GET` | `/api/reports/export/excel` | Export filtered logs as Excel |

### Leave Requests
| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/leaves` | Submit leave/WFH request |
| `GET` | `/api/leaves/my` | Get personal leave requests |
| `GET` | `/api/leaves/pending` | Admin — get pending requests |
| `POST` | `/api/leaves/{id}/approve` | Admin — approve a request |
| `POST` | `/api/leaves/{id}/reject` | Admin — reject a request |

### Dashboard (Admin)
| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/dashboard/stats` | Live KPI stats (present, absent, late) |
| `GET` | `/api/dashboard/qr` | Generate daily QR code |

## 🔒 Security

- **JWT Bearer Tokens** — Stateless authentication with 24-hour expiry
- **Role-Based Access Control** — `ROLE_ADMIN` and `ROLE_EMPLOYEE` roles with route-level protection
- **Password Encryption** — BCrypt password hashing
- **CORS Configuration** — Restricted to frontend origin
- **GPS Verification** — Check-in rejected if outside geofence radius
- **Face Matching** — Biometric face descriptor comparison at check-in
